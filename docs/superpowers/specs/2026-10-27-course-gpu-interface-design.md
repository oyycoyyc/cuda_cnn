## 2. 规则事实与不确定项

课程要求：CMake 生成 `train`、`infer`，源码包含根目录 `CMakeLists.txt` 和 `.cu`；禁止 Dockerfile。调用为：

```text
train images.f32 labels.i32 N C H W K work_dir
infer images.f32 N C H W K
```

图像为 FP32 连续 NCHW，训练标签为 int32。训练将模型保存到 `work_dir`，推理通过 `COURSE_MODEL_DIR` 找到该模型。推理 stdout 恰好 N 个按原顺序排列的整数类别；诊断均写 stderr。推理不读取测试标签。

规则未说明两件事：图像 float32 的数值范围／是否标准化，以及排行榜 `Test Time` 的计时边界。不能从 0.14 ms 排行数字反推出初始化是否计入。两项均不得冒充已确认课程事实。

### 设计者提出的输入默认值（须用户确认）

- 默认课程图像是 `[0,1]` 的 FP32 灰度值，以 GPU 计算 `(x - 0.1307) / 0.3081`；不得先转换成 uint8 或重复除以 255。
- 显式支持训练时选择 `COURSE_INPUT_MODE=unit|byte|normalized`：unit 如上；byte 对 `[0,255]` 浮点先除 255；normalized 对已经按相同均值／标准差处理的有限 FP32 直接使用。默认 unit；这是项目额外选项，不是课程保证会设置的变量。
- 训练时的模式随模型以版本化元数据保存；推理只使用模型记录的模式，不根据测试图像值域猜测、不被运行时同名环境变量覆盖。
- unit/byte 检查有限值与相应范围；normalized 检查有限值。超出明确契约时报错，不自动切换模式。
- 现有模型仅支持 `C=1,H=28,W=28,K=10`；不支持的形状明确失败，不假装支持任意 CNN 输入。N 为任意合法正整数，不写死 10000，验收集使用完整 10000 张。

若课程预处理后来得到不同说明，必须调整并验证默认设置；在此之前只能证明与所声明输入模式一致，不能声称已通过未知的线上数据预处理。

## 3. 方案选择

1. **用户选择：保留 LeNet，课程适配＋独立推理路径。** 复用已验证的训练核及数值定义，先去掉推理时不需要的梯度、优化器、随机初始化、标签统计和逐批读回。风险可控，可与原权重作全量对照。
2. **暂不实施：更小 CNN 并重新训练。** 可利用 96% 准确率门槛缩小计算，但会增加训练和准确率验证成本，且不能自动解决 CUDA 首次初始化。

不采用 CPU 推理、常驻进程隐藏启动、平台预加载绕过或变更驱动配置。

## 4. 代码边界与构建

- 在根目录新增课程 `CMakeLists.txt` 和 `main.cu`，后者通过 `COURSE_TRAIN` / `COURSE_INFER` 分别生成两个入口；禁止同时定义或都未定义时意外生成可用入口。
- 新课程组件集中于 `course/`：参数／数据接口、模型元数据、训练适配、独立前向存储与推理、少量新增输入及 argmax CUDA 辅助核。现有 `src/main.cu`、原 CLI 和 Makefile 的既有功能保留。
- 复用 `src/` 下的 LeNet 训练类、参数／检查点处理、随机与分割工具和自有 CUDA 算子。`infer` 不依赖旧 `RunInfer`、训练工作流、测试标签、Python 或测试工具。
- CMake 最低版本 3.18；C++14 / CUDA14，REQUIRED；默认 H20 架构 90，同时允许调用者通过 `CMAKE_CUDA_ARCHITECTURES` 指定，不写死个人机器路径。基线优化等级与现有实现匹配，不默认启用 fast-math 或混合精度。
- 新测试与旧 Make 合规清单的连接由实现计划明确处理，不能为了增加源码而破坏已有的精确清单扫描；也不能让课程目标依赖诊断／快照工具。构建清单变化需要回归测试。
- 首轮仍为项目自有 FP32 CUDA 实现，不新增 cuDNN/cuBLAS/框架等依赖，不把课程允许选择网络误解为已授权取消原有第三方库限制。

## 5. 课程数据接口

- 训练恰好 8 个位置参数，推理恰好 6 个位置参数（均不含程序名）；严格解析正整数，拒绝溢出、非法维度和额外参数。
- `.f32` / `.i32` 为无头的四字节元素数组；验证平台表示和文件精确长度 `N*C*H*W*4` / `N*4`，所有乘法有溢出检查，拒绝短文件、尾随数据及 NaN/Inf。
- 训练 int32 标签先验证 `[0,K)`，再为复用现有 GPU 损失核无损转换为 uint8。推理不打开任何标签文件、不猜测旁路路径。
- 输入、标签、已有权重只读；课程模型只写到调用者提供的工作目录，避免与输入文件或其别名碰撞。目录不存在时仅创建指定输出目录，不改变挂载权限。
- 主机可解析、组织批次及验证文件；归一化、前向、预测类别计算均在 GPU 上执行。

## 6. 模型交接与训练适配

- 模型包为 `work_dir/lenet.bin`（复用现有检查点布局）及一个小型版本化文本元数据文件（准确名字／严格语法由实现计划确定），记录网络标识、C/H/W/K、输入模式和固定标准化契约。
- `infer` 必须验证 `COURSE_MODEL_DIR`、两个文件、模式／版本／形状、全部权重的有限性；不静默回退到原工程 `weights/`、当前目录或其他绝对路径。缺文件、坏模型、CUDA 失败均返回非零，stderr 说明错误。
- 原检查点的标准化字段保持其固定定义，额外输入模式写在课程元数据，不让旧加载器误读；元数据与模型需要完整交接，写入失败不留下被当成有效新模型的半包。
- 新训练适配不能直接调用旧 `RunTrain`：它要求另一个带标签测试集，违反课程训练输入契约。改为复用其底层 `LeNet` 前后向和 AdamW，以及既有确定性打乱／验证分割策略；仅访问传入的训练图像与训练标签。
- 默认种子 1337、批大小 128、20 epochs、既有分段学习率和 AdamW 超参数；从训练集划出验证集，仅按验证准确率选择最佳权重，训练日志写 stderr。N 较小时明确使用有训练／验证样本的确定性分割，N<2 时训练失败。
- 为有界回归测试可显式设置 `COURSE_EPOCHS`，默认 20，合法范围 1..1000；测试必须恢复环境，正式结果记录实际配置。它不是推理必要参数，也不是课程要求变量。
- FP32 图像的训练批次和增强使用新增适配，不经 uint8 量化。平移增强的背景值必须与所记录输入模式的黑色像素定义一致，不能对 normalized 模式填错零。
- 原生产权重不覆盖。用现有权重验证独立前向时，在实验目录创建明确输入模式的测试模型包；正式课程 `train` 必须实际生成可供 `infer` 使用的模型，不以打包既有模型代替训练。
- 本轮验收包括默认完整训练以及所产生模型的外部全量测试，不能用已有权重的准确率代替。先用一个 epoch 估算资源和耗时，再进行默认训练；若明显超过可用会话／资源预算，如实标为未完成而非跳过。默认配方未达到 96% 时保留失败结果，不能静默改网络或训练口径；训练配方调整先提出并记录。

## 7. 独立 GPU 推理路径

- 新推理专用模型只拥有权重、必要前向激活和工作缓冲；不创建梯度／AdamW 状态、不生成随机权重再覆盖、不对整池做无意义初始化。
- 首轮复用现有 Conv→ReLU→Pool→Conv→ReLU→Pool→FC→ReLU→FC→ReLU→FC 的数学顺序，FP32 及最小类别索引打破并列的规则保持不变。in-place ReLU 等存储复用只在现有核契约允许且验证后使用。
- 复用现有池化前向核时，它仍需要 winner 输出；可保留小型 winner 缓冲，但不能谎称整个推理路径没有这项存储。无需实现后向。
- 只输出类别，不计算无用 softmax、不上传标签、不调用需要标签的正确数统计核。新增不依赖标签的 GPU argmax，将预测写入全量设备输出区。
- 读入全部图像，按经过检查的容量分批上传／归一化／前向／argmax。默认先用可复现实测批量 1024，正确处理所有末批；之后对 128/1024/更大可行批量作有限测量选择，不在每批动态分配显存。
- 输入、权重只验证一次；每个输出行在 GPU argmax 中检查 logits 的有限性，聚合错误标志。若调试需要可 opt-in 扫描中间激活，不能让生产路径盲目忽略非法输出或异步 CUDA 错误。原训练安全检查仍保留。
- 单流顺序执行，权重／工作区／所有 N 个预测／错误标志预分配，批次循环内不做显存分配或主机读回。结束后一次读回预测和错误标志并同步，检查成功后一次性写 stdout，避免错误时输出部分预测。
- stdout 每行一个十进制类别整数，共 N 行；无设备说明、准确率、计时、logits 或额外标题。所有诊断写 stderr，不读取隐藏测试标签。错误返回非零，成功返回 0。

## 8. 计时与性能决策

- 外部单调时钟记录从新建 `infer` 进程到它退出的完整墙钟，包括图像／模型读取、CUDA 初始化、传输、前向、检查、输出和退出。沿用全量数据、不预先将初始化移出计时、不用常驻服务替代。
- 同时提供明确命名的内部阶段时间和 GPU forward 时间：数据／模型读取、CUDA／分配准备、H2D、GPU 前向＋argmax、D2H／检查、输出。GPU Events 与主机阶段边界必须写清；首次请求包含在测量，不自动预热后只取热态最好值。
- 默认 fast path 不为分段计时增加逐批同步；分段诊断与最终无诊断基准分开。完整 GPU 算法时间若不含传输，必须明确标注，不能在结果图中简称为同口径的完整 `Test Time`。
- 独立进程至少 5 次，保存全部结果、中位数、最大值、配置和二进制／模型 SHA-256；低于 100 ms 与准确率至少 96% 必须对应同一模型、全量样本和声明口径。
- 目前已知同平台首次 CUDA API 超过 1 秒。这不是证明其他环境／排行榜不可能更快，但意味着本设计不能预先承诺完整进程 <100 ms。不得用达到了内部 forward <100 ms 来宣布完整目标成功。
- 若初始化仍占绝大部分，报告事实并将下一步集中于课程正式环境／计时规则的核实，不重新跑已完成的 36 次启动诊断，不绕过平台库，不盲目重写卷积。
- 接口／数值测试通过只代表本轮功能可交付；完整时间仍大于 100 ms 时，用户的性能目标明确标为“未达标”，不把内部计时作为替代 gate。阶段完成和性能目标满足必须分开写。

## 9. 测试与验收

### 不需要 GPU 的接口测试

- 严格参数、维度／尺寸乘法溢出、精确文件大小、FP32 NaN/Inf、标签界限、模型元数据解析和未知版本。
- unit/byte/normalized 三种模式的明确定义及序列化；禁止根据推理样本自动切换；确保推理接口没有标签输入路径。
- 所有拒绝／路径保护测试仅使用临时自有目录和模拟挂载，不用真实数据挂载作写入试探。
- 输出校验恰好 N 个范围内整数，错误时无部分预测；诊断只出现在 stderr。

### H20 数值／运行时测试

- 单张、批大小 17、1024、N 不整除批量；对同一已规范化 FP32 输入缓冲、同一权重，要求新旧前向 logits 逐位一致、预测逐张一致；本轮不改变计算核的算术／归约顺序。in-place ReLU 只改变合规存储别名，不得改变数学运算。输入格式转换／预处理另测，不把旧 uint8 转换与新 FP32 输入在舍入上的差别混入 forward 一致性测试。不把更低的 96% 门槛当作掩盖接口 bug 的许可。
- 构建 train / infer，两者按正式位置参数运行。真实完成一个有界训练→模型保存→新进程 infer 的闭环，无测试标签参与训练或推理。
- 用原权重的独立推理完整跑本地已知 MNIST 测试集；准确率由外部验证器用标签计算，infer 本身不可读取标签。原模型已知 9911/10000 作为回归参照。
- 默认课程训练的完整训练／验证和独立测试评估另记耗时及模型来源。若尚未跑完，不把原权重的 99.11% 当成新训练模型已达标的证据。
- 复查旧主机／CUDA／工作流及构建合规回归。远程缺 pyarrow、Sanitizer 自行禁用等既有限制继续如实记录，不宣称全绿。
- 验收 `.f32` / `.i32` 输入由本项目开发用的标准库转换工具从既有只读 MNISTC1 数据生成，包含 unit/byte/normalized 三种明确模式；写入独立实验目录，不写数据挂载、不修改原文件、不依赖新增 Python 包。它只做格式转换，不计算神经网络；不进入提交包或课程运行依赖。外部验证器拥有本地测试标签，课程 infer 无此访问路径。
